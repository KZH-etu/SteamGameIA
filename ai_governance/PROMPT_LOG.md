### Entry 1 – Loading and inspecting the review and game files (Module 1 – Yohan ALLOUCHE)
- **Goal:** load `recommendations.csv` (41M rows) and the two game files (Kozyriev `games.csv`, FronkonGames `games_1.csv`) with compact dtypes, and inspect shape, dtypes, % missing and duplicates, without dropping or imputing anything.
- **Bare prompt (v1):** "I have `recommendations.csv` (41M rows; columns: app_id int, helpful int, funny int, date str YYYY-MM-DD, is_recommended bool, hours float, user_id int, review_id int) and `games.csv` (app_id, title, date_release, win, mac, linux, rating, positive_ratio, user_reviews, price_final, price_original, discount, steam_deck). Write pandas code that loads only app_id, date, is_recommended, hours, helpful from recommendations with compact dtypes (int32, bool, float32), parses dates, and prints shape, dtypes, % missing per column and the number of duplicated rows. Do not drop or impute anything yet. Tell me the expected memory usage and how to read the file in chunks if I have less than 12 GB of RAM."
  → problem with the answer: the code loaded the full 41M-row file into memory and the kernel crashed (see AI_AUDIT, Flaw 1). The answer was also over-engineered (a long helper function computing statistics chunk by chunk) and hard to explain line by line.
- **Constrained prompt (v2):** v1 + "Work on a development sample (`nrows=5_000_000`) instead of the full file. Keep the code minimal: plain pandas calls, no helper functions, no memory estimation. Also load FronkonGames `games_1.csv` with `usecols`, after fixing its header: the column `DiscountDLC count` must be split into `Discount` and `DLC count`, otherwise every column after `Price` is shifted by one."
- **What we kept / changed:** kept the compact dtypes and the date parsing with `errors="coerce"` (unreadable dates become NaT and are counted, not dropped). Removed the memory estimation. Added a note explaining that identical rows are not real duplicates (two players can post the same review values on the same day), so they are not dropped. Checked the FronkonGames alignment with `head(3)`: without the header fix, the `AppID` column contained game names and no game matched Kozyriev; with the fix, 39,436 app_id are shared (77.5% of Kozyriev games).

### Entry 2 – Building `reviews_clean` and `games_clean` (Module 1 – Yohan ALLOUCHE)
- **Goal:** produce `reviews_clean.parquet` (app_id, date, days, is_recommended, hours, helpful) and `games_clean.parquet` for Module 2 (target) and Module 3 (features).
- **Bare prompt (v1):** "My teammate needs reviews_clean, generate it."
  → problem with the answer: it only produced the reviews. A game with zero reviews is absent from `reviews_clean`, so Module 2 could not give it `n_reviews_1y = 0` and would silently drop it (survivorship bias). A `games_clean` table with all sampled games was also needed.
- **Constrained prompt (v2):** "Select the games released between 2015 and 2021 in the Kozyriev games table and draw a random sample of 10,000 app_id (`random_state=SEED`). Read `recommendations.csv` in chunks of 2M rows and keep ALL reviews of these games: never sample individual review rows. Compute `days` = review date − release date (Kozyriev `date_release`), count the reviews with `days < 0` (early access), exclude them, and save `reviews_clean.parquet`. Then left-join the sampled games with FronkonGames (`AppID` renamed to `app_id`) with `validate="one_to_one"` and `indicator=True`, report how many games are kept or missing in FronkonGames, and flag release dates that differ by more than 30 days. Drop the columns measured after release (rating, positive_ratio, user_reviews, price_final, discount, steam_deck, FronkonGames `Price`), rename the columns to snake_case and save `games_clean.parquet`. Keep the code minimal."
- **What we kept / changed:** `N_GAMES` is a parameter (`None` = all 2015-2021 games). The release date comes from Kozyriev (base table); the FronkonGames date is only used for the consistency check. An `assert` checks that no review date is unreadable, so that no row is silently lost by the `days >= 0` filter. `dlc_count` and `tags` are kept but flagged as a leakage risk (they may have changed after release), to be discussed in Module 3.

### Entry 3 – Static features and early signals (Module 3 – Jason ZOH)
- **Goal:** build `features_static.parquet` (variables known at release, T = 0) and `features_T{7,30,90}.parquet` (early review signals) from `games_clean` and `reviews_clean`, then run the EDA and the leakage audit.
- **Bare prompt (v1):** "Let's start my Module 3: build the features from games_clean and reviews_clean."
  → problem with the answer: the request says neither which columns are known at release nor where the train split comes from (Module 2 has not delivered `target.parquet` yet). Nothing prevents computing the tag frequencies on all games, or using every column of the review table as a signal.
- **Constrained prompt (v2):** "From games_clean [price_original, win, mac, linux, required_age, languages, release_date, description, genres, categories, tags], build features known at release time: log1p(price), is_free, platform flags, n_languages, release month and weekday, description length, and multi-hot encoding of genres/categories/tags keeping only values present in at least 1% of TRAIN games. Module 2 is not merged yet: recompute the same time-based split (oldest 70% = train, next 15% = val, last 15% = test) only to select the tags. Then for each T in [7, 30, 90], compute per game from reviews with `0 <= days < T`: n_reviews, pos_ratio, mean and median hours. Start from all games: n_reviews = 0 when there is no review, pos_ratio and hours stay NaN, add a has_reviews flag, no imputation. Add an assert that no review with days >= T is used. For each column, tell me whether it could have changed after release and flag it as a leakage risk. Keep the code minimal."
- **What we kept / changed:** `n_languages` counts the commas of the text list (`"['English', 'French']"`) + 1, with `"[]"` set to 0; the first version with `ast.literal_eval` crashed (AI_AUDIT, Flaw 3). Added an `in_fronkon` flag, because a game absent from FronkonGames gets 0 in every tag column. Removed `dlc_count` and the release year (see the leakage audit in the notebook), and removed the helpful votes and the hours played, which are both read at collection time, after T (AI_AUDIT, Flaw 2). The correlations use Spearman instead of Pearson, because `n_reviews` is very skewed. The temporary split must be replaced by the `split` column of `target.parquet` as soon as Module 2 delivers it.
